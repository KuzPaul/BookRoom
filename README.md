# BookRoom — бронирование переговорных

Веб-приложение для поиска свободных переговорных, создания бронирований и управления ими.

**Страницы:**
- `/rooms` — список переговорных с фильтрами
- `/rooms/:roomId` — расписание комнаты и создание бронирования
- `/bookings` — мои бронирования


## Что нужно для запуска

- **Node.js 20+**
- два терминала: один для backend, один для frontend

---

## Как запустить

### 1. Backend (порт 3000)

```bash
cd server
npm install
cp .env.example .env
npm run dev
```

Backend будет доступен на `http://localhost:3000`.

### 2. Frontend (порт 5173)

В **другом** терминале:

```bash
cd client
npm install
npm run dev
```

Открой в браузере: **http://localhost:5173**

Frontend ходит в API через прокси

## Архитектура проекта

Код frontend разложен по папкам — каждая отвечает за свою часть:

```
client/src/
├── app/           # роутинг и провайдеры (React Query)
├── pages/         # страницы-обёртки для маршрутов
├── modules/       # логика экранов
│   ├── rooms/         # список переговорных
│   ├── room-detail/   # страница комнаты и бронирование
│   └── bookings/      # мои бронирования
└── shared/        # общее для всего приложения
    ├── api/           # запросы к backend
    ├── lib/           # утилиты (даты, WebSocket)
    ├── layout/        # шапка и общий layout
    └── ui/            # переиспользуемые UI-компоненты
```

**Как это работает:**
1. `pages/` — тонкая обёртка, подключает модуль
2. `modules/` — основная логика экрана (фильтры, списки, модалки)
3. `shared/api/` — все HTTP-запросы в одном месте
4. `shared/lib/date.ts` — правила времени (рабочий день 9:00–20:00, шаг 15 мин, максимум 30 дней вперёд)

## Выбранные технологии

| Технология | Зачем |
|---|---|
| **React 19 + TypeScript** | UI и типизация — требование задания |

| **Vitest** | Unit-тесты |
| **WebSocket** | Real-time обновления без перезагрузки страницы |

## Real-time обновления
Приложение подключается к WebSocket (`/api/v1/ws`).

Когда на сервере создают или отменяют бронирование, клиент получает событие и **обновляет данные через React Query** — без перезагрузки страницы.

Обновляются:
- список доступных комнат на `/rooms`
- расписание открытой комнаты на `/rooms/:roomId`

События группируются с debounce 200 ms, чтобы не делать лишних запросов.

## Принятые решения

### Последний выбранный офис запоминается
На `/rooms` последний офис сохраняется в `sessionStorage`. При возврате на страницу офис подставляется автоматически.

### Переход с `/rooms` на страницу комнаты
При клике «Забронировать» на карточке комнаты открывается `/rooms/:roomId?startsAt=...&endsAt=...` — модалка бронирования сразу с выбранным временем из фильтров.

### Конфликт бронирования (409)
Если комната уже занята, показывается модалка «Конфликт бронирования», расписание обновляется.

### Оптимистическая отмена
На `/bookings` при отмене бронирование сразу исчезает из списка. Если сервер вернёт ошибку — карточка возвращается обратно.

### Reconnect WebSocket
Базовое переподключение есть (при размонтировании сокет закрывается).
